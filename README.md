# 00 학원 평가 도우미

문제지 PDF·정답지 PDF·OMR 인식 결과 XLSX를 업로드하면 자동 채점하고, 통계와 학생별 정오답을 엑셀로 내려받습니다. 채점 결과 질문과 유사 문제 생성은 같은 화면에서 사용합니다.

## 로컬 실행 (Windows / Python 3.12)

프로젝트 폴더에서 실행합니다. 기존 가상환경을 그대로 사용합니다.

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

브라우저에서 [로컬 앱](http://localhost:8501)을 엽니다. `서비스 소개`와 `채점·분석` 두 페이지가 있습니다.

새 환경에서 설치한다면 먼저 `python -m venv .venv`, 이어서 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`를 실행합니다.

## 비밀 설정

`.streamlit/secrets.toml`에 아래 항목을 작성합니다. 이미 입력한 키 파일은 덮어쓰지 마세요. 실제 키는 GitHub·채팅·스크린샷에 노출하지 않습니다.

```toml
OPENAI_API_KEY = "실제 키"
OPENAI_MODEL = "gpt-5.4-mini"
```

앱은 Streamlit secrets 또는 같은 이름의 서버 환경변수를 읽습니다. `.env` 파일을 자동으로 읽지는 않습니다. 키가 없어도 채점·엑셀 다운로드는 가능합니다. 모든 AI 채팅 답변에는 키가 필요하며, 키가 없을 때 고정 문장으로 AI 답변을 대신하지 않습니다.
기본 모델은 `gpt-5.4-mini`, reasoning effort는 `none`입니다. 모델을 변경한다면 Responses API·Structured Outputs·이미지 입력과 `none` 지원 여부를 확인하세요.

### Supabase (후속 설정)

현재는 로컬 기능을 먼저 사용하도록 되어 있습니다. DB 미연결·저장 실패가 채점·다운로드를 막지 않습니다.

1. Supabase SQL Editor에서 `supabase/schema.sql`을 실행합니다.
2. 기존 secrets 파일에 아래 항목을 **추가**합니다.
3. 앱을 재시작하고 분석하거나 `DB 저장 다시 시도`를 누릅니다.

```toml
SUPABASE_URL = "https://프로젝트.supabase.co"
SUPABASE_SECRET_KEY = "서버용 secret 키"
```

기존 프로젝트의 `SUPABASE_SERVICE_ROLE_KEY`도 지원합니다. publishable/anon 키는 쓰지 않습니다.
`exam_results` 한 테이블에 실행별 결과를 원자적으로 upsert합니다. RLS를 켜고 anon/authenticated 접근을 차단합니다. 서버는 현재 세션에서 생성한 실행 ID만 저장하며, 과거 시험 조회 API는 제공하지 않습니다. 서버 키는 브라우저로 전달하지 않습니다.
원본 파일과 대화는 DB에 저장하지 않습니다. 계정별 장기 재열람·로그인은 현재 범위에 없습니다.

## 입력과 사용

- 텍스트가 포함된 문제 PDF와 `문항 번호 / 정답 / 배점` 정답 PDF를 준비합니다. 원문자 정답 ①~⑤ 또는 숫자 1~5를 읽습니다.
- 응답 XLSX는 `OMR_응답` 시트(없으면 첫 시트), 첫 열 `학생명`, 나머지 `Q01`, `Q02` 등의 문항 열을 사용합니다.
- 파일당 20MB, PDF 30쪽, 학생 5,000명, 문항 200개 이내입니다. 초기 추출기는 수능형 2단 또는 단순 1단 텍스트 PDF를 대상으로 합니다. OCR·원본 OMR 이미지 인식은 제공하지 않습니다.
- 완전히 빈 행은 제외합니다. 미응답은 오답(0점)으로 채점하고 엑셀에 구분합니다. 중복 학생·문항 누락·수식·잘못된 선택지는 오류로 안내합니다.
- 세 파일 업로드 후 `분석 시작`을 누르면 채점 결과·다운로드·채팅이 활성화됩니다. 파일을 바꾸면 재채점 전까지 이전 결과를 사용할 수 없습니다.
- 통계는 코드로 계산합니다. 표준편차는 모집단 기준(ddof=0)입니다. 오답 동률은 문항 번호가 작은 순서로 선택합니다.
- 다운로드 시트는 `전체 개요`, `학생별 결과`, `문항별 분석`입니다.

질문 예:

- 학생들 이번 시험 점수 평균이랑 중앙값이 뭐야?
- 가장 성적이 저조한 학생은 누구야?
- 903학생은 어떤 문항이 부족해? → 어떤 문항이 부족한건데?
- 900번 학생 몇 점이야? → 그 학생 점수 다시 알려줘.
- 학생들이 가장 많이 틀린 문제와 유사한 유형으로 문제 1개 만들어.
- 33번과 유사한 문제 만들어.

답변 아래에는 실제 모델과 API 호출 횟수를 표시합니다. 학생 조회는 점수뿐 아니라 오답 문항·선택 답·정답·문항 유형을 분석할 수 있습니다. 학생 조회는 행 순서가 아닌 엑셀의 학생명과 대응합니다. 없는 학생·출석 등 없는 정보는 추측하지 않습니다. 내부 설정·도구 공개 요청을 거절합니다.
대화는 현재 세션에만 보관하며 새 시험의 채점을 완료하면 초기화합니다. 최근 대화 40개를 화면에, 최근 20개를 문맥으로 유지합니다.

### OpenAI로 전달되는 데이터

모든 채팅은 Responses API가 질문과 최근 대화로 필요한 도구를 선택하고, LangGraph가 조회한 근거로 OpenAI가 최종 답변을 작성합니다. 학생 조회에는 해당 학생의 점수·오답 번호·선택 답·정답·문항 지시문이 전달됩니다. 시험 개요 조회에는 계산된 통계와 최저/최고 성적 학생 정보가 전달됩니다. 문항 상세 조회에는 해당 원문·정답·배점이 전달됩니다. 유사 문제 생성에는 선택 문항 텍스트·정답·해당 페이지 이미지(최대 3쪽)를 전달합니다. 전체 응답표를 한꺼번에 보내지는 않습니다.
문항 페이지에는 같은 쪽의 다른 문항도 포함될 수 있습니다. API 호출은 `store=False`를 사용하지만 별도의 서비스 데이터 보존 정책까지 변경하는 설정은 아닙니다. 데이터 전송이 허용된 시험 자료로 사용하세요.
듣기 문항은 음원 대신 대본형 문제를 생성합니다. AI가 생성한 문항의 정답·해설은 수업 사용 전에 교사가 검토해야 합니다.
한 턴에 도구 실행은 최대 2회 묶음(묶음당 최대 4개), 최종 작성까지 모델 호출은 최대 3회로 제한합니다. 문제 생성에는 추가 생성 호출이 포함되며 한 턴에 새 문제는 1개만 생성합니다. 총 18초 예산과 재시도 없는 요청을 사용합니다. API 지연·한도·망 상태에 따라 실패할 수 있으며, 타임아웃 안내는 평가 정답으로 간주하지 않습니다.

## 검증

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q app.py grading.py agent.py storage.py tests
```

테스트는 합성 데이터를 사용하며 키 없이 실행합니다. 실제 입력 파일과 키는 저장소에 커밋하지 않습니다. 실행 결과와 남은 확인 사항은 `docs/verification.md`에 기록합니다.
