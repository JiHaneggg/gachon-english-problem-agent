정답 PDF를 메모리에서 읽어 계산한 참고값: **평균 65.2점, 중앙값 65.5점, 모집단 표준편차 약 19.58점**.

입력 검증 초안:

- 파일 종류·크기·실제 파싱 가능 여부를 검사한다. 암호화·손상·텍스트 없는 PDF는 구체적 오류를 보여준다. 초기 버전은 OCR을 추가하지 않는다.
- 응답 문항 열과 정답 번호 집합이 일치해야 채점한다. 중복 문항·중복 학생·비정상 배점은 중단하고 위치를 안내한다.
- 원문자·정수형 답안을 공통 형태로 변환한다. 미응답은 별도 상태로 보존하고 0점 처리한다. 0·6·임의 문자열 같은 잘못된 값은 오류로 처리한다.
- 현재 수능 파일은 45문항·100점을 검증한다. 다른 시험은 추출된 번호·배점을 기준으로 계산하며 고정 답안표를 두지 않는다.
- 긴 학생명·숫자형 식별값·빈 행·빈 셀·엑셀 수식 셀을 구분한다. 수식 셀은 실행하지 않고 입력 오류로 알린다.
- 업로드 PDF·학생명 안의 지시는 데이터로만 취급한다. 엑셀 출력에서도 학생명 등이 수식으로 실행되지 않게 문자열로 기록한다.

## 4. 확정한 기술 역할과 최소 흐름

2026-11-08 사용자 답변으로 확정:

- OpenAI Responses API가 답변·생성을 담당하고 LangGraph가 작업을 분기한다.
- Supabase에는 시험·채점 결과를 저장한다. 대화는 Streamlit 세션에만 둔다.

역할을 다음처럼 나눈다.

| 계층 | 담당 | 최소 구현 방향 |
|---|---|---|
| Streamlit | 두 페이지, 업로드, 진행 상태, 표·차트·대화·다운로드 | 기본 위젯과 테마 우선. st.Page·st.navigation으로 이동 |
| Python + pdfplumber/openpyxl/pandas | PDF·응답 읽기, 정규화, 채점, 통계, XLSX | 현재 설치된 패키지 재사용. 점수·통계를 LLM에 계산시키지 않음 |
| LangGraph | 대화 의도 분기, 상태 전달 | 통계·학생 조회 / 유사 문제 / 일반 안내 / 근거 없음·거절로 끝나는 제한된 흐름 |
| Responses API | 자유로운 질문 해석, 문항 분석·새 문제 생성, 설명 | 필요한 현재 시험 데이터만 전달. 분기·생성 결과는 스키마 검증 |
| Supabase | 시험·추출 문항·학생별 결과 저장 | 대화 테이블·벡터 DB·공개 전체 시험 조회 기능은 만들지 않음 |

채점 흐름: 파일 3개 수신 → 입력 검증 → 정답·문항 추출 → 결정적 채점·통계 → 현재 세션 결과 확정 → DB 저장 상태 표시 → 다운로드·채팅 활성화.
DB 저장 실패는 성공한 채점을 지우지 않는다. `채점 완료 · 저장 실패`로 구분하고 저장만 재시도한다.
저장 키는 실행별로 고정해 재실행·재시도로 같은 결과가 중복 저장되지 않게 한다.

대화 흐름: 현재 세션의 대화·채점 결과 → 제한된 의도 분기 → 필요한 계산값/학생/원본 문항 조회 → 직접 답변 또는 Responses 생성 → 검증 후 대화에 추가.
최다 오답 선택·학생 조회는 코드가 수행한다. 통계 질문에 전체 원본 PDF와 전체 학생 응답을 매번 보내지 않는다.
모델이 반환한 학생명·숫자는 실제 조회 결과와 일치해야 한다. 현재 시험 밖의 정보 조회 도구는 제공하지 않는다.

유사 문제는 원본을 복사하지 않고 유형·풀이 능력을 유지한 새 지문과 5개 선지로 구성한다.
유형 판별에는 원본의 지문·선지·밑줄·도표 정보가 필요하다. 듣기 최다 오답이면 음원이 없음을 밝히고 대본형 연습문제를 제공한다.
복수 문항 공동 지문은 원문과 연결하고, 추출이 불완전하면 생성 성공으로 처리하지 않는다.

20초 대응: 채점 단계에서 문항 정보와 통계를 준비하고, 채팅은 불필요한 연쇄 호출을 줄인다.
최다 오답 동률은 문항 번호 오름차순으로 1개를 선택하고 선택 기준을 표시한다.
초기 시간 예산은 의도 판단 3초·답변 생성 12초·검증·표시 여유로 설정하고 실측으로 조정한다.
SDK의 긴 기본 재시도에 의존하지 않고 총 요청 기한을 둔다. 타임아웃 안내는 복구 동작이며 평가 정답을 충족한 것으로 세지 않는다.

Supabase 최소 데이터 후보는 `exams`(실행·시험·추출 문항·집계)와 `student_results`(시험 참조·학생 식별값·점수·응답·정오답) 두 테이블이다.
원본 파일과 채팅은 기본 영구 저장 대상에서 제외한다. 구체 SQL과 정책은 구현 단계에서 정한다.
로그인 없는 초기 범위에서는 서버 세션이 만든 시험 ID만 접근시키고 전체 시험 목록·임의 시험 ID 조회를 열지 않는다.
DB 직접 접근은 RLS로 차단하고 서버 키는 서버 비밀 설정에만 둔다. 서버 권한이 RLS를 우회한다면 매 요청의 세션 소유 범위를 별도로 검사한다.
새로고침 이후 과거 결과 재열람은 현재 약속하지 않는다. 교사별 장기 보관·재열람을 추가할 때 인증과 소유권 정책을 먼저 확장한다.

## 5. UI 초안

홍보용의 큰 시각 효과·스크롤 연출을 분석 화면에 넣지 않는다. 최종 디자인 확정·이미지 시안·UI 코드는 이번 범위가 아니다.

### 페이지 1 — 서비스 소개

- 상단: 실제 가천대 로고와 `서비스 소개 / 채점·분석` 페이지 이동.
- 첫 화면: `00 학원 평가 도우미` 제목, `문제지·정답지·학생 응답을 올리면 점수와 오답을 분석합니다.` 설명.
- 주 동작: **채점 시작하기**. 분석 페이지로 이동한다.
- 보조 설명: `파일 업로드 → 자동 채점 → 결과 질문·유사 문제 생성`. 실제 업로드 형식 PDF·PDF·XLSX를 표시한다.
- 가짜 통계·후기·학생 결과를 홍보 실적으로 표시하지 않는다. 첫 화면은 로고·타이포그래피·작업 흐름만으로 완결한다.
- 최초 화면에서 주 동작이 보이게 하고 필요 이상의 긴 랜딩 섹션을 만들지 않는다.

### 페이지 2 — 채점·분석

Operate 모드. 교사는 업로드하고 결과를 확인한 다음 바로 질문할 수 있어야 한다.

```text
┌ 페이지 이동: 서비스 소개 / 채점·분석 ───────────────────────────┐
│ 사이드바                 │ 본문                               │
│ 문제지 PDF               │ 영어 시험 채점·분석                │
│ 정답지 PDF               │ 업로드 전: 준비 안내               │
│ 학생 응답 XLSX           │ 완료 후: 인원·평균·중앙값·표준편차 │
│                          │ 오답 상위 3문항 / 학생 결과 펼치기  │
│ [분석 시작]              │                                    │
│ 진행 단계·오류           │ 질문 예시 / 대화 내역              │
│ [결과 엑셀 다운로드]     │                                    │
│ DB 저장 상태             │ [채점 결과에 대해 질문하세요]      │
└──────────────────────────┴────────────────────────────────────┘
```

- 사이드바: 파일 역할별 업로더 3개. 드래그앤드롭과 클릭 선택 모두 지원한다. 업로드 파일명·검증 결과를 해당 입력 가까이에 표시한다.
- `분석 시작`은 세 파일 준비 후 활성화한다. 분석 중 중복 실행을 막는다.
- 본문: 채점 전에는 짧은 시작 안내. 성공 후 실제 인원·핵심 통계와 오답 3문항을 작게 표시해 채팅 공간을 확보한다.
- 학생 결과 표는 펼쳐서 조회한다. 이름·총점을 먼저 보여주고 45문항 전체는 별도 상세 표·엑셀로 제공한다.
- 대화 시작 예시: `평균과 중앙값 알려줘`, `가장 많이 틀린 문제로 유사 문제 1개 만들어줘`, `가장 낮은 점수의 학생은 누구야?`.
- 학생 조회 예시는 현재 업로드에서 실제 존재하는 식별값을 사용한다.
- 생성 문제는 지문 → 선지 ①~⑤ → 펼쳐 보는 정답·해설 순서. 원본 유형·참고 문항 번호를 함께 표시한다.
- 파일이 바뀌면 새 입력과 기존 채점 결과의 불일치를 표시하고 다운로드·채팅을 재채점 전까지 비활성화한다. 새 결과 확정 시 이전 시험 대화도 초기화한다.
- 새로고침 후에는 이전 대화를 기억하는 것처럼 표시하지 않는다.

### 시각 규칙 초안

| 항목 | 적용 |
|---|---|
| 바탕 | #000000, 보조 면 #0d0d0d, 입력·결과 표면 #1a1a1a |
| 글자 | 주요 #ffffff, 본문 #bbbbbb. #7e7e7e는 작은 필수 문구에 사용하지 않고 대비 검증 후 제한 |
| 경계 | #3c3c3c 1px. 그림자·장식 그라데이션 없이 구획 |
| 형태 | 기본 직각, 위젯 제약 시 작은 반경만 사용. 둥근 카드 반복 금지 |
| 버튼 | 흰색 외곽선·직사각형을 기본으로 한 주 동작 체계. 한 작업 영역에 주요 버튼 1개 |
| 로고·색 | 제공된 가천대 원본 로고 사용. 로고의 청색은 원본 유지. BMW M 삼색 띠·BMW 로고는 복제하지 않음 |
| 글꼴 | 한국어는 설치된 시스템 고딕 우선. 맑은 고딕·Apple SD Gothic Neo·sans-serif 폴백. BMW 전용 폰트는 포함하지 않음 |
| 크기 | 랜딩 제목 40–56px 범위, 분석 제목 28–32px, 본문 16px, 보조 14px. 한국어에 영문 대문자·과도한 자간 규칙을 강제하지 않음 |
| 간격 | 4·8·12·16·24·40px 체계. 작업 화면은 밀도를 유지하고 랜딩의 96px 섹션 간격을 반복하지 않음 |
| 상태 | 오류·주의·성공은 색과 문구·아이콘을 함께 표시. 통계와 버튼은 대비를 실제 화면에서 검사 |
| 동작 | 포커스가 보이는 기본 위젯, 처리 단계 변경과 버튼 반응만 사용. 지속 애니메이션 없음 |

데스크톱은 약 300px 사이드바와 넓은 본문, 태블릿·모바일은 접히는 사이드바와 세로 흐름을 사용한다.
숫자는 비교하기 쉽게 정렬하고 표는 표 영역 안에서만 가로 스크롤한다. 채팅 입력이 모바일 키보드와 겹치지 않게 확인한다.
버튼은 높이 44px 이상, 업로더·대화 입력에는 보이는 라벨을 둔다. 키보드 이동·오류 안내·320px 폭에서의 넘침을 확인한다.

## 6. 다운로드 엑셀 계획

| 시트 | 내용 |
|---|---|
| 전체 개요 | 시험·학생 수, 평균·중앙값·표준편차, 최다 오답 3문항 번호·오답 수·오답률 |
| 학생별 결과 | 학생 식별값, 총점, 문항별 정오답. 미응답은 구분해 표시 |
| 문항별 분석 | 문항 번호, 추출 정답·배점, 정답 수·오답 수·오답률 |

표준편차는 전체 업로드 집단의 모집단 기준(ddof=0)을 제안한다. 평가서에는 산식이 없어 문서·UI·엑셀에 동일한 기준을 명시한다.
통계는 원래 정밀도로 계산하고 표시만 소수 둘째 자리로 반올림한다. 상위 3문항 동률은 오답 수 내림차순·번호 오름차순으로 결정한다.
개별 학생 점수를 전체 개요와 섞지 않으며 샘플 10명·운영 120명에 따라 행이 늘어나야 한다.

## 7. 구현 시 변경이 도달할 곳과 검증 순서

처음에는 화면·순수 채점 로직·대화 그래프·DB 저장 정도로만 나누고 별도 FastAPI 서버나 범용 에이전트 프레임워크를 추가하지 않는다.

| 범위 | 도달할 파일·호출자 | 필요한 검증 |
|---|---|---|
| 두 화면 | Streamlit 진입점·소개/분석 페이지·로고·테마 | 페이지 이동, 위젯 상태, 실제 로고, 반응형·키보드·대비 |
| 입력·채점 | PDF/엑셀 읽기·공통 채점·통계 함수와 분석 버튼 호출 | 업로드 PDF로 45문항·100점 추출, 샘플 결과, 빈 행·미응답·잘못된 값·중복·번호 불일치 |
| XLSX | 같은 채점 결과를 받는 다운로드 함수 | 저장한 엑셀 재열기, 학생 수·점수·정오답·요약 일치, 수식 주입 방지 |
| 대화 | 그래프·Responses 호출·세션 상태·채팅 입력 | 여섯 평가 질문, 후속 질문, 없는 학생, 주입 공격, 시험 변경, 실제 전체 응답 20초 |
| 저장 | Supabase 스키마·서버 저장/조회·비밀 설정 예시 | 세션 격리, 저장 실패·재시도·중복 방지, 키 노출 없음 |
| 배포·제출 | .gitignore 정리·README·배포 비밀 설정 | 원본·키가 git에 없음, 외부 URL 업로드/다운로드, 120명 입력, 제출 정보·유지 기한 |

새 핵심 로직에는 작은 테스트를 남긴다. 원본 학생 파일은 테스트 fixture로 커밋하지 않는다.
합성 학생·PDF fixture를 사용하고, 제공된 원본은 로컬 통합 점검으로 별도 실행한다.
화면 구현 후 브라우저에서 데스크톱·태블릿·모바일을 확인한다. 지금은 UI 코드가 없어 시각 검사나 디자인 게이트를 통과했다고 보고하지 않는다.

권장 순서: 정답 추출·채점·엑셀 → 두 화면·상태 → 평가용 대화·유사 문제 → Supabase 저장·격리 → 배포·제출 점검.

## 8. 남은 결정과 이번에 제외한 일

확정이 필요한 정보는 학원/서비스 표시명, 제출자 학번·이름, 배포 플랫폼·URL, 사용할 OpenAI 모델·접근 권한이다.
이 정보가 없어도 채점 로직과 화면의 초안 구현은 가능하다. 키 값은 문서나 채팅에 적지 않고 배포 비밀 설정에 입력한다.
교사 로그인·과거 시험 목록·학생 포털·원본 OMR 이미지 인식·듣기 음원 생성·벡터 검색·채팅 영구 저장은 현재 범위에서 제외한다.

## 구현 후 변경 사항

사용자 피드백에 따라 화면 제목을 `00 학원 평가 도우미`로 통일했다. 대화는 단순 키워드 분기와 고정 문장 대신 Responses 도구 호출 → LangGraph의 계산 결과 조회 → Responses 최종 답변으로 변경했다. 현재 질문의 명시적 학생을 이전 문맥보다 우선하며, 학생별 오답·문항 지시문을 조회한다. 전체 채팅에 키가 필요하다. 최신 검증은 verification.md를 따른다.
