## 판정과 개선 절차

1. 모델의 조회 요청, 실제 반환 학생·수치, 최종 문장, 생성 문제를 별도로 기록한다.
2. 질문 조건 전체와 20초 내 완성을 함께 본다. 타임아웃 안내·추가 번호 요청은 생성 성공이 아니다.
3. 생성 문제는 원본 유형·새 지문·선지 5개·정답 유일성·해설 연결을 읽어 확인한다. 형식 검증기만으로 의미적 정확성을 보장하지 않는다.
4. 실패를 모의 API 회귀 테스트로 먼저 재현한 뒤 공통 로직을 수정한다. 새 의도 분기·모델 교체로 증상을 가리지 않는다.
5. 변경한 질문 계열을 실제 API로 다시 시험한다. 수정 전 실패와 수정 후 결과를 함께 남긴다.
6. 로컬 결과와 배포 서버의 업로드·다운로드·DB 저장·두 세션·완료 시간을 따로 기록한다.

자동 회귀 검사: `python -m unittest discover -s tests -v`. 실제 API 기록에는 키·원본 학생 자료를 넣지 않는다.
