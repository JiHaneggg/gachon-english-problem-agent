# 구현·검증 기록

## 대화 품질 수정 후 최신 검증 (2026-11-08)

이 절이 현재 버전의 결과다. 아래 최초 구현 기록은 수정 전의 검증 범위를 보존한 것이다.

- 규칙 기반 의도 분기·고정 성적 답변을 제거했다. Responses 함수 호출 → LangGraph 조회 → Responses 최종 답변으로 변경했다.
- 학생 조회는 점수와 오답 번호·선택 답·정답·문항 지시문을 반환한다. 듣기·독해·미확인 유형별 개수는 코드로 집계한다.
- 현재 질문의 학생이 명시되면 이전 문맥이나 모델의 잘못된 조회 인수보다 우선한다. 없는 학생을 이전 학생으로 대체하지 않는다.
- 모든 정상 채팅 답변에서 OpenAI를 사용한다. 내부 도구 공개 요구는 도구 실행을 차단하고 최종 출력도 거절로 제한한다. 키가 없으면 AI 응답을 흉내 내지 않는다.
- 답변 아래 실제 API 응답의 모델명과 호출 횟수를 표시한다. 이전 생성 문제의 내용도 다음 대화 문맥에 포함한다.
- 화면·브라우저 제목을 사용자가 지정한 `00 학원 평가 도우미`로 변경했다. 실제 1440px 캡처로 확인했다.
- 회귀 테스트 **27/27 PASS**, compileall·git diff --check PASS, 디자인 detect `[]`.
- 실행문 커버리지(기존 세션 참조 보정 직전 측정) **528/606줄 = 87.1%**. app 90.8%, grading 84.2%, agent 86.6%, storage 91.3%.
- 기존 열린 세션의 잘못된 학생 참조만 한 번 초기화하며 대화·채점 결과는 보존한다. 이 보정을 포함한 최종 테스트도 27/27 PASS.
- 실제 키와 Git 포함 후보 대조: 키 노출 없음. 새 의존성·비밀 파일 변경 없음.
- 사용자 승인을 받아 특정 학생 1명의 해당 정보만 OpenAI에 전송했다. 처음 질문·생략된 후속 질문·명시적 정정 질문에서 같은 학생과 실제 오답 15문항을 유지했다. 시험 결과 파일은 Git에서 제외된 outputs에만 기록했다.
- 실제 서비스의 전체 도구 목록에서도 필요한 학생 조회를 선택했다. 최종 영역별 개수까지 채점 결과와 일치했고 약 **3.81초 / OpenAI 2회**로 완료했다. 요청 직전에 승인된 학생 정보만 전송되는지 감사했다.
- 합성 데이터로 평균·중앙값, 최저 학생, 특정 점수, 없는 출석 정보, 도구 공개 거절을 실제 API에서 확인했다.
- 생성 흐름의 실제 API 시험에서 빈칸 없는 빈칸 문제와 본문 중복 표시를 발견해 보완했다. 빈칸/밑줄 표시 검증을 추가하고, 완성된 문제는 별도 문제 UI에서 한 번만 표시한다. 합성 빈칸 문제 재검증은 약 **4.55초 / OpenAI 3회**로 완료했다.
- 정적 타입·전용 린트 도구는 여전히 미설치이며, Supabase·배포는 이번 수정 범위가 아니다. 소수 실측이 모든 질문의 정확성이나 20초 응답을 보장하지는 않는다.

## OpenAI 실제 검증

- 키 값 출력·수정 없이 gpt-5.4-mini Responses 호출 성공. 짧은 연결 시험 약 2.75초.
- 실제 자료 전송 시험은 자동 승인 심사에서 처음 거절되었다. 실제 시험·학생 자료를 외부로 보내는 명시적 동의가 부족하다는 이유였다.
- 이후 사용자가 **문항 지문·선지·정답·해당 PDF 페이지 이미지만 OpenAI에 보내는 1회 시험**을 승인했다. 학생명·학생 응답은 해당 생성 요청에 포함하지 않았다.
- 승인된 생성 1회: 21번 유형의 새 문제, 5개 선지·정답·해설, 지문 135단어, 전체 약 5.12초. 생성물은 Git에서 제외된 `outputs/verified-exercise.json`에 보관했다.
- 자유로운 표현의 의도 분류는 실제 학생 자료 없는 합성 통계로 검증했다. Responses 분류 후 로컬 통계 답변까지 약 2.05초.
- 6개 평가 질문 계열은 테스트에서 확인했다. 생성 외의 명확한 평가 질문은 로컬 조회·정해진 거절 경로를 사용한다.
- 20초 이내는 이번 소수 시험 결과이다. 반복·동시 접속·배포 환경의 응답 시간 보장은 하지 않았다.

## UI 검증

- 소개/분석 페이지 이동, 업로드 전 비활성화, 처리·오류·완료, 채팅·후속 질문, 엑셀 다운로드를 확인했다.
- 320·390·768·1280px 브라우저 폭과 1440px 소개 스크린샷을 확인했다. 모바일 사이드바를 열고 닫아 이동·업로드가 가능했다.
- 확인한 320·390·768px에서 문서의 가로 넘침이 없었다. 모바일 제목·소제목 크기와 단어 줄바꿈, 짧은 채팅 안내를 조정했다.
- 소개 화면 캡처: `outputs/shots/home-desktop.png`. 검정·흰색·직각 구조, 제공된 가천대 로고를 사용했다.
- CSS와 고정 제목에만 HTML을 허용한다. 사용자 파일·질문·모델 답변은 HTML 허용 없이 렌더링한다.
- 키보드 포커스 스타일·대비·축소 동작을 작성하고 시각 검토했다. 전체 스크린리더·모든 위젯의 대비 자동 감사는 미실행.
- 마케팅용 전체 화면 섹션·효과를 요구하는 taste gate는 이 Streamlit 작업 화면의 수용 기준으로 사용하지 않았다. `GATE: PASS`를 주장하지 않는다.
